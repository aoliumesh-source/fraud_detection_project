# AI-Driven Fraud/Default Risk Detection Framework

**Module:** 7005SCN — Individual Research Project
**Artefact for:** An AI-Driven Framework for Real-Time Fraud Detection in Digital Payment Systems Using Machine Learning and Predictive Analytics

This is the software artefact supporting the project report. It implements the
methodology described in Section 4 of the proposal: data preprocessing, four
comparative ML models, SHAP-based explainable AI, a Low/Medium/High risk
scoring system, and an interactive Streamlit dashboard.

> **Note on the dataset:** the proposal's dataset source (UCI *Default of
> Credit Card Clients*) is a credit-default dataset, used here as the
> proxy for "high-risk transaction/customer behaviour" as described in the
> methodology — it does not contain a labelled fraud flag. This should be
> stated explicitly as a scope/limitation in the report's Methodology and
> Evaluation sections.

## How to run

```bash
pip install -r requirements.txt

# Run the full analysis pipeline (preprocessing -> training -> SHAP -> risk scoring)
cd src
python main.py

# Then launch the interactive dashboard from the project root
cd ..
streamlit run app/streamlit_app.py
```

Each script can also be run individually and in order if you want to inspect
intermediate outputs:

```bash
python src/data_preprocessing.py
python src/train_models.py
python src/shap_explain.py
python src/risk_scoring.py
```

## What each step produces (useful for report figures)

| Step | Script | Key outputs |
|---|---|---|
| 1. Preprocessing & EDA | `data_preprocessing.py` | `processed_data.csv`; class distribution, correlation heatmap, PAY_0 vs default rate, age distribution figures |
| 2. Model training | `train_models.py` | 4 trained `.joblib` pipelines, `model_comparison_metrics.csv`, confusion matrices, ROC curve comparison, metric bar chart, classification reports |
| 3. Explainability | `shap_explain.py` | SHAP beeswarm + bar plots, `shap_feature_importance.csv`, single-customer waterfall plot |
| 4. Risk scoring | `risk_scoring.py` | `risk_scored_customers.csv`, `risk_band_summary.csv`, risk distribution + validation charts |

## Results summary (test set, 20% holdout, stratified)

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| XGBoost | 0.762 | 0.470 | 0.604 | 0.529 | **0.771** |
| Random Forest | 0.781 | 0.506 | 0.549 | 0.526 | 0.768 |
| Decision Tree | 0.776 | 0.494 | 0.552 | 0.522 | 0.753 |
| Logistic Regression | 0.683 | 0.372 | 0.633 | 0.469 | 0.719 |

XGBoost was selected as the production model (highest ROC-AUC — the most
appropriate metric here given class imbalance ~78/22).

Top SHAP predictors of default risk: `PAY_0` (most recent repayment status) by
a wide margin, followed by `BILL_AMT1`, `LIMIT_BAL`, and recent payment
amounts — consistent with the literature reviewed in Section 3.

Risk-band validation (does higher predicted risk mean higher actual default?):

| Risk Band | Customers | Actual Default Rate |
|---|---|---|
| Low Risk | 2,707 | 9.0% |
| Medium Risk | 2,056 | 20.5% |
| High Risk | 1,230 | 53.7% |

The monotonic increase confirms the risk-scoring logic is behaving sensibly.

## Reproducibility

- Random seed fixed at 42 throughout (`RANDOM_STATE` in `config.py`).
- Train/test split is stratified 80/20 on the target variable.
- All class-imbalance handling (`class_weight='balanced'`, `scale_pos_weight`)
  is documented inline in `train_models.py`.
